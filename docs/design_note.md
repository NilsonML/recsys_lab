# Design note: recsys-lab

**Автор:** aleksejhanykov85 · **Дата:** 2026-10-20 · **Статус:** draft

## Задача

Построить и честно сравнить алгоритмы top-K рекомендаций на implicit feedback.
Для каждого пользователя выдаём ранжированный список из K фильмов, которых он ещё не видел.

- **Данные:** MovieLens-1M (~1M оценок, 6 040 пользователей, 3 706 фильмов, 2000–2003 гг.).
- **Implicit:** оценка ≥ 4 считается позитивом, остальное отбрасываем. Применяем 5-core фильтрацию по пользователям и айтемам.
- **Вне скоупа:** онлайн-сервинг, A/B-тесты, cold start для новых пользователей.

## Метрики

| Метрика | Роль |
|---|---|
| **NDCG@10** | основная, по ней выбираем модель |
| Recall@{10,20,50} | полнота; Recall@50 важен для кандидатогенерации |
| MAP@10 | вспомогательная метрика ранжирования |
| Catalog coverage@10 | защита от вырождения в популярное |

- Метрики считаем по всем айтемам (full ranking, без сэмплирования негативов) и исключаем уже просмотренное.
- Популярность — обязательный бейзлайн. Модель, которая не обгоняет её по NDCG@10, не засчитывается.
- Улучшение подтверждаем на 3 seed'ах: среднее ± std.

## Ограничения

- **Железо:** ноутбук на Windows, только CPU. Обучение одной модели укладывается в ≤ 10 минут.
- **Без утечек:** сплиты строим по времени (`leave_last_out`, `temporal_global`). Гиперпараметры подбираем только на val, test открываем один раз.
- **Воспроизводимость:** фиксированный seed, конфиги в Hydra, каждый запуск попадает в MLflow вместе с полным resolved-конфигом.
- **Качество кода:** ruff, mypy (strict) и pytest проходят на каждом коммите через pre-commit.

## План

1. **Инфраструктура** ✅: src-layout, Poetry, Hydra, MLflow, линтеры, CI-хуки.
2. **Данные:** загрузка, препроцессинг, оба сплита, тесты на отсутствие утечек.
3. **Оценка:** метрики с unit-тестами на ручных примерах и evaluator для full ranking.
4. **Бейзлайны:** Popularity, ItemKNN, EASE^R.
5. **Факторизация:** ALS, BPR-MF.
6. **Нейросети:** NCF и two-tower с ANN-retrieval (кандидатогенерация + ранжирование).
7. **Отчёт:** таблица результатов в `EXPERIMENTS.md` и выводы.

## Риски

- **Popularity bias.** Сильный popularity-бейзлайн на ML-1M часто сложно обогнать. Смотрим на coverage, а не только на NDCG.
- **Чувствительность к сплиту.** Random split и temporal split дают разные выводы, поэтому отчитываемся по обоим temporal-сплитам.
